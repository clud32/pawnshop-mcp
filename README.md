# 深空当铺 MCP

这是给《深空当铺》（Probably Stolen）玩家用的 AI 经营助手。遇到一笔拿不准的买卖时，你可以直接问：「这件货值得收吗？买完还交得起房租吗？」接入后，聊天里的 AI 能读取你最近保存的账本和库存，结合游戏里的物品资料帮你算账。最后由你在柜台上出价。

## 它解决什么问题

查攻略能知道某件物品的基础价。决定要不要收眼前这件货，还得看它的品相、真假、店里已经囤了多少同类货，以及离下次交租还有几天。这些信息分散在物品、库存、账单和手册里。通过 MCP，AI 可以自己查，再把影响这笔交易的数字摆在一起。

举个例子。假设你有 **480 信用点**，本期房租 **300**，还有 **50** 欠租。顾客开价 **160**，收货后手里只剩 **320**，距离交租要凑齐的 **350** 还差 **30**。这时最有用的追问是「我的展柜里有哪些货可以先卖？」助手可以列出库存里的单件估值，并标出损坏或假货。能卖多少钱，还取决于顾客和实际成交价。

## 谁适合用

| 你遇到的情况 | 可以直接问 |
| --- | --- |
| 刚开店，拿不准一件货该出什么价 | 「这件东西的基础价是多少？我库存里那件为什么估值低了这么多？」 |
| 店里货很多，付租时却经常缺现金 | 「我几天后交租，算上欠租要留多少钱？展柜里哪些货占着资金？」 |
| 玩了几周，想弄清钱花在哪，或隔了几天回来接档 | 「上周现金和净资产分别怎么变了？我当时记下的下周计划是什么？」 |

适合在 Windows 上玩游戏、希望边玩边用中文问问题的玩家。接好客户端后就能用自然语言提问，也可以让助手按你的剧透偏好和经营目标回答。[陪玩提示词](陪玩提示词.md)

## 本地运行

准备 64 位 Python 3.11、Windows 版游戏和一个支持 MCP 标准输入输出（stdio）的客户端。服务使用 Python 标准库，在 CPU 上建立和检索索引。

**1. 下载项目，确认能读到自己的档位。** 在 PowerShell 里运行以下命令，把游戏目录换成本机安装位置。运行 `saves` 后可按游戏天数、开局身份和最近保存时间核对档位。

```powershell
git clone https://github.com/clud32/pawnshop-mcp.git
cd pawnshop-mcp
$env:PS_GAME_DIR = "D:/SteamLibrary/steamapps/common/Probably Stolen"
python -X utf8 server.py saves
```

**2. 在聊天客户端添加服务。** 下面的示例适用于使用 `mcpServers` 的客户端。把脚本路径换成 `(Resolve-Path ./server.py).Path` 显示的绝对路径，游戏目录与上一步保持一致。如果客户端找不到 Python，把 `command` 换成 `(Get-Command python).Source` 显示的路径。JSON 路径可以使用正斜杠。

```json
{
  "mcpServers": {
    "pawnshop": {
      "command": "python",
      "args": ["-X", "utf8", "D:/repos/pawnshop-mcp/server.py"],
      "env": {
        "PS_GAME_DIR": "D:/SteamLibrary/steamapps/common/Probably Stolen"
      }
    }
  }
}
```

**3. 重新加载服务，问第一句话。** 试试「用深空当铺工具看一下，现在是第几天，手头有多少现金，离交租还有几天？」拿回答和最近一次保存时的游戏画面对一下。刚完成的交易可能要等游戏再次保存才会反映在余额和库存里。

<details>
<summary>存档、周报和个人笔记的位置</summary>

默认存档目录为 Windows 用户目录下的 `AppData/LocalLow/Questing Goose Studio/Probably Stolen`。如果存档放在别处，用 `PS_SAVE_DIR` 指向含 `saves_index.es3` 的文件夹。`auto` 读取最近保存的档位，也可以通过 `save` 参数指定档位号。

服务只读游戏安装目录和存档，把查询结果返回给客户端。周报、经营日志、个人笔记及索引缓存写入仓库根目录下的 `.local/`，可以用 `PS_STATE_DIR` 改位置。读取局面时可能自动补出已到期的周报。随项目提供的攻略笔记在 `kb_seeds/`，个人新增笔记写入状态目录的 `kb_seeds/`。

## 工具与数据来源

| 想查的事 | 工具 | 判断依据 |
| --- | --- | --- |
| 现金、租金、贷款、库存，以及刚才的顾客做了什么 | `saves`、`overview`、`save_get`、`inventory`、`gamelog` | 最近保存的档位、物品状态、游戏日志 |
| 这周钱花在哪，之前做了什么决定 | `weekly_report`、`weekly_plan`、`journal` | 以交租日为界的现金与净资产记录、已有周报快照，以及玩家记下的计划和决定 |
| 物品用途、开局天赋、配方和难度规则 | `kb_search`、`kb_get`、`kb_add_seed`、`kb_rebuild` | 中英文本地化、手册、攻略笔记，以及从本地 Unity 资源和 .NET 程序集读出的部分数值 |

估价时，`unitValue` 是这件库存物品考虑品相和真伪后的单件数值，`baseValue` 是能从游戏代码中查到的基础价。查房租涨幅时，可以让助手用 `kb_get` 读取难度表 `num:difficulty`，再对照当前档位的难度、租金和欠租。

知识库用 BM25 检索，中文按单字和相邻双字切分。`kb_search` 返回片段和文档 ID，`kb_get` 按 ID 读整篇，游戏更新后可用 `kb_rebuild` 重新索引。周报按实际保留的数据复盘。补写旧周报时，若当时没有快照，只能从存档的每日序列和已记日志中还原那一周。

## 测试环境声明

2026-11-24 在 Windows 11 家庭中文版（10.0.26200，AMD64）、CPython 3.11.9 64 位、Steam 游戏 Build ID `26525552` 上测试。集成测试使用本机游戏资源与最近保存的档位，从空缓存和临时状态目录启动服务，通过 stdio 使用 MCP 协议 `2025-06-18`。[完整测试记录](tests/results.json)

## 测试结论

| 检查项目 | 结果 |
| --- | --- |
| 合成存档回归 | 6/6 通过，覆盖协议握手、工具发现、读档、未知工具、笔记写入范围，以及大库存下的经营总览。 |
| 真实存档集成 | 发现 12 个工具，实际调用 7 个，完成读档、查现金、解析展柜库存、检索和生成周报。档位索引和读取的存档在测试前后 SHA-256 一致。 |
| 攻略检索 | 从本机游戏和 21 条随附笔记构建 2,855 篇文档。120 个问题中，95 个首条命中（79.2%），110 个前三条命中（91.7%）。 |

命中指检索结果包含题目标注的任一参考文档。10 个问题在前三条中未找到参考资料，包括用俗称找熔炉、间接询问人情点来源。本轮统计衡量检索效果，最终回答质量、实际经营收益、其他系统和桌面客户端界面均未评测。[评测题集](tests/queries.tsv)

本项目的 120 题包括五类问法各 10 题，以及 70 道追加改写题。下表的两组各取自首批 50 题。两个版本逐题使用相同的参考文档 ID。两个版本的题目文字一致，随附笔记的内容有差异。

| 评测版本 | Top-1 | Top-3 | 省略专名 Top-3 | 条件对照 Top-3 |
| --- | ---: | ---: | ---: | ---: |
| 本地原项目 | 96/120 | 110/120 | 9/10 | 10/10 |
| 本仓库开源版 | 95/120 | 110/120 | 9/10 | 10/10 |

下方评测命令使用仓库随附的笔记，输出开源版总分、各组命中数和未命中问题。完整分组统计见 [tests/results.json](tests/results.json) 的 `retrieval.by_group`（开源版）和 `local_reference.by_group`（本地原项目）。

在仓库根目录运行以下命令即可复查。第一项使用合成存档，第二项读取本机游戏与存档，第三项重建索引并输出命中统计。

```powershell
python -X utf8 -m unittest discover -s tests -v
python -X utf8 tests/live_smoke.py
python -X utf8 tests/evaluate.py
```
